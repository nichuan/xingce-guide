# Xingce Guide · 行测六大模块学习网站

A single-file static learning site for the Chinese civil service exam (公务员考试《行政职业能力测验》). It covers all six modules — 言语理解与表达、政治理论、判断推理、常识判断、数量关系、资料分析 — with an outline, technique checklists and fully explained worked examples.

The whole site is generated from **one Markdown file** into **one self-contained `index.html`**: no backend, no account, no CDN, no tracking, no network requests at runtime. It runs from `file://` just as well as from GitHub Pages, so students can download it and study offline.

Live site: <https://nichuan.github.io/xingce-guide/>

## What is included

- **10 chapters / 41 learning units / 32 worked examples / 45 tables**, covering question types, formulas and speed-calculation tricks for every module.
- **Chapter tree navigation** — three levels (chapter → section → topic), collapsible, with scroll-spy highlighting and a mobile drawer.
- **Full-text search** — highlights every match in place, with match counter and next/previous jumping (`/` to focus).
- **Study progress** — a "已掌握" checkbox per unit, progress bar and persistence in `localStorage`.
- **Collapsed solutions** — every example hides its explanation behind a `<details>` toggle, so learners attempt the question first.
- **Presentation mode** — hides the sidebar and enlarges type for classroom projection.
- **Light/dark themes, five font sizes**, and a `@media print` stylesheet that strips the UI, expands all solutions and avoids page breaks inside tables and examples.
- **Keyboard shortcuts** — `/` search, `Enter` / `Shift+Enter` next & previous match, `j` / `k` next & previous unit, `?` help, `Esc` close.

## Stack and choices

- **Pure Python 3 standard library** for the build — no `pip install`, no `node_modules`, nothing to audit. The only dependency is a Python interpreter.
- **Single output file** instead of a bundler: the content is ~90 KB of Markdown, so an SSG framework would add far more machinery than it removes.
- **Content kept in `src/guide.md`**, never edited in the generated HTML. One source of truth, regenerated by CI on every push.
- **A generated-site self-check** (`scripts/check_site.py`) runs in CI before deploy: HTML tag balance, leftover Markdown markers, inline JS syntax and structural counts.

## Local development

Python 3.9+ is enough; 3.12 is what CI uses.

```bash
make build     # src/guide.md -> dist/index.html
make check     # validate the generated site
make serve     # build, then serve dist/ on http://localhost:8080
```

`make build` uses exactly the same arguments as the GitHub Actions workflow.

## Editing the content

All prose lives in `src/guide.md`. The build script understands a small convention:

| Markdown | Rendered as |
|---|---|
| `# H1` | page title only (not part of the body) |
| `## H2` | chapter, top level of the sidebar tree |
| `### H3` | **learning unit** — gets a "已掌握" checkbox, appears in the sidebar and counts towards progress |
| `#### H4` | topic inside a unit |
| `> quote` | callout box |
| `**示例 N**` … `**解析**` | example card with the solution collapsed by default |
| GFM tables / fenced code | horizontal-scroll table / monospace block |

`src/guide.docx` is the Word edition of the same content and is published alongside the site as a download.

## Deployment

`.github/workflows/pages.yml` builds and deploys to GitHub Pages on every push to `main`:

1. build `dist/index.html` from `src/guide.md`;
2. copy the Word edition into `dist/`;
3. run the generated-site self-check;
4. upload `dist/` as the Pages artifact and deploy it.

Pull requests run steps 1–3 only, so a broken build never reaches the published site.

## Project layout

```
├── scripts/

├── src/

```
